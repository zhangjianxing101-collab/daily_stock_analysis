# 同花顺金融数据接入设计

## 目标

将同花顺金融数据 API 接入协作日报系统，覆盖 A 股实时行情、历史 K 线、财务指标、热榜和行业/同花顺指数，同时保留现有数据源作为可审计的降级路径。系统必须支持本地结构化查询和交易日定时报表复用，且不得自动下单或承诺收益。

## 范围

- 新增以 `THS_API_KEY` 配置的同花顺 REST 客户端，使用 `X-api-key` 请求头。
- 新增 A 股代码到带市场后缀 `thscode` 的规范化映射。
- 将行情快照、历史 K 线接入 `MarketDataGateway` 的首选数据路径。
- 将财务指标、热榜、行业/同花顺指数接入选股和报告证据。
- 新增面向本地人工查询的结构化命令入口。
- 增加客户端、转换、回退、异常与报告证据的离线测试。

不包含自动下单、密钥落盘、密钥输出、改写用户持仓，或以任何数据源结果保证收益。

## 架构

### 客户端边界

`ThsMarketDataClient` 是唯一访问同花顺 REST API 的模块。它负责：

- 从运行环境读取 `THS_API_KEY`，不记录密钥、请求头或完整 URL 日志。
- 处理超时、网络失败、HTTP 错误以及响应信封中的业务错误。
- 解析服务的统一 `ApiResponse` 信封，校验返回数据类型、时间戳和必填字段。
- 产出标准化、与供应商无关的数据模型。

调用方只依赖标准模型，不依赖服务端字段命名或接口路径。

### 网关与回退

`MarketDataGateway` 以同花顺为 A 股首选来源：

1. 对实时行情和历史 K 线，先请求并验证同花顺数据。
2. 对可恢复的失败（超时、临时网络错误、缺权限、无有效数据），回退至既有来源。
3. 对数据质量失败（未来时间戳、错误 OHLC、陈旧数据、无效价格）不将该数据作为交易结论依据。
4. 报告记录来源、数据时间与降级警告；缺少可信价格时为观望，而非生成交易信号。

若关键价格与已有可信来源明显冲突，系统进入只提示状态，保留冲突证据并停止该标的的方向性结论。

### 数据能力

| 能力 | 用途 | 最终行为 |
| --- | --- | --- |
| 行情快照 | 持仓估值、盘中筛选、风险检查 | 首选来源，失败回退 |
| 历史 K 线 | 技术指标、回测 | 首选来源，失败回退 |
| 财务指标 | 基本面筛选、报告证据 | 缺失时降级，不伪造数值 |
| 热榜 | 短线热度与候选股排序 | 仅作证据与排序，不单独构成买卖建议 |
| 行业/同花顺指数 | 行业强弱与市场环境 | 仅作证据与风险背景 |

### 查询入口

协作报告 CLI 增加人工查询子命令，以股票、指数或热榜为输入，输出结构化 JSON 或表格摘要。该入口与日报共用相同客户端与校验逻辑，避免两套数据语义。

## 安全与配置

- GitHub Actions 仅从 Repository Secret `THS_API_KEY` 注入运行环境。
- `.env.example` 仅提供空变量名，不提供真实密钥。
- 测试使用伪造响应和伪造密钥；禁止真实网络调用和密钥打印。
- 所有投资结论附带人工确认要求；风险、数据降级或价格冲突时优先观望。

## 错误处理

- `THS_API_KEY` 缺失：禁用同花顺客户端，使用已有来源并报告配置缺失。
- 鉴权或权限错误：不重试，不暴露响应细节，降级并提示管理员检查权限。
- 限流、超时、5xx：受限重试后降级；不阻塞整份日报。
- 无效或陈旧响应：拒绝该响应，保留简短数据质量告警。
- 全部数据源不可用：报告不可生成交易信号，保留风险与人工确认提示。

## 验证

- 客户端鉴权、错误信封、超时和重试测试。
- `thscode` 映射与所有数据模型的字段转换测试。
- 行情/K 线校验和回退路径测试。
- 财务、热榜、指数在筛选和报告中的证据测试。
- CLI 查询测试与密钥不泄露测试。
- 手动连通性检查必须显式执行，并只报告成功/失败和请求 ID 摘要。

## 回滚

通过移除 `THS_API_KEY` 或关闭同花顺提供方配置即可停用该来源；已有来源继续工作。若代码回滚需要恢复，执行对该功能提交的 `git revert`，无需迁移数据或轮换其他系统配置。
