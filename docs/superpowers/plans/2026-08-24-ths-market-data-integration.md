# 同花顺金融数据接入实施计划

> 设计：`docs/superpowers/specs/2026-08-24-ths-market-data-design.md`

## 1. 配置和共享模型

修改 `src/collaborative_report/settings.py`、`src/collaborative_report/models.py`、`.env.example` 和测试配置。

- 增加非持久化 `THS_API_KEY` 读取、基础 URL、请求超时和提供方启用开关。
- 增加 `thscode`、数据来源时间、数据质量警告和专题数据的稳定模型。
- 确认默认环境和错误信息不包含密钥。
- 测试：环境变量缺失、非法设置、模型序列化和密钥脱敏。

## 2. 同花顺 REST 客户端

新增 `src/collaborative_report/ths_market_data.py` 与对应测试。

- 实现统一请求函数：`X-api-key`、超时、有限重试、API 响应信封解析及请求 ID 摘要。
- 实现 A 股快照、历史 K 线、财务指标、热榜、同花顺指数目录/成分/快照/K 线调用。
- 业务错误、鉴权错误、限流、空结果和畸形响应映射为明确的、无敏感信息的异常。
- 测试：每个端点的正常响应、错误信封、网络失败、超时与请求头不出现在日志中。

## 3. 标的标准化与数据校验

修改 `src/collaborative_report/market_data.py` 与测试。

- 将沪市、深市、北交所 A 股代码映射为完整 `thscode`；拒绝无法确定市场的输入。
- 将同花顺快照/K 线转换为现有规范列，并验证时间戳、OHLC、成交量与交易日新鲜度。
- 对财务、热榜和指数建立只读标准化函数；保留来源和原始时间语义。
- 测试：所有市场后缀、异常日期/价格、字段缺失和时间戳时区。

## 4. 主来源与降级策略

修改 `MarketDataGateway`、`runner.py` 与测试。

- A 股快照和 K 线优先调用同花顺；可恢复失败时调用已有来源。
- 同花顺数据质量失败时拒绝使用，不生成基于该数据的交易结论。
- 当两个可信来源的关键价格显著冲突时，返回观察状态、记录告警并阻断方向性信号。
- 测试：同花顺成功、鉴权失败、超时、回退、数据冲突和全来源失败。

## 5. 筛选、风险和报告证据

修改 `screener.py`、`risk.py`、`report.py`、`runner.py` 及测试。

- 将财务指标纳入基本面证据，将热榜和行业/同花顺指数纳入候选排序与市场环境。
- 这些数据仅提升或降低证据权重，不能独立产生买卖指令。
- 在 HTML/邮件报告展示来源、数据时间、降级/冲突状态和人工确认提示。
- 测试：专题数据出现在报告中；缺失或异常专题数据时报告仍安全生成且为观望或降级。

## 6. 人工查询入口

修改 `cli.py`、文档与测试。

- 新增 `collaborative-report query` 子命令，支持 `quote`、`bars`、`financials`、`hot-list`、`index` 查询。
- 输出结构化 JSON，并提供可选简洁表格；不输出密钥或完整请求头。
- 用与日报相同的客户端、标准化和错误处理逻辑。
- 测试：命令参数、成功输出、无密钥、供应商失败与错误码。

## 7. 工作流、文档与验证

修改 `.github/workflows/01-collaborative-report.yml`、`docs/collaborative-report.md`、`.env.example` 与测试。

- 将 `THS_API_KEY` 作为 GitHub Secret 注入，仅在协作报告任务使用。
- 更新密钥配置、数据能力、降级语义和人工连通性检查文档。
- 运行协作报告测试、通知/工作流契约测试和完整关键回归集。
- 仅在用户明确确认后执行一次手动 GitHub Actions 测试；测试邮件继续使用 `test_email=true`。

## 完成标准

- 同花顺全量能力可由人工查询，行情/K 线驱动现有日报与回测路径。
- 数据异常时系统明确降级或观望，不泄露密钥，不自动下单。
- 所有新路径均有离线测试；线上连通性通过显式人工确认后再验证。
